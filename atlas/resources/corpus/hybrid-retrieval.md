# 混合检索：为什么单一检索器不够

纯稠密向量检索擅长语义泛化，但对精确的编号、型号、专有名词和代码标识符很弱。纯稀疏检索（如 BM25）擅长精确词命中，却无法理解同义改写。工业界结论已经收敛：把两路召回的结果做融合，比任何单路都好。

本文约定：稠密检索负责语义召回，稀疏检索负责精确召回，融合层负责把两路不可比的分数变成可比的排名。之所以不能直接对分数做加权求和，是因为余弦相似度落在 [0,1] 而 BM25 的分数是无上界的，二者的尺度依赖语料与查询，逐查询做 Min-Max 归一化在存在极端离群点时非常不稳定。

## 为什么选择倒数排名融合

倒数排名融合（Reciprocal Rank Fusion，Cormack 等人 2009 年提出）只使用排名，不使用分数：

- 对每一路召回结果，文档 d 的贡献是 weight / (k + rank(d))，其中 rank 从 1 开始计数。
- 默认 k 取 60。k 越大，头部排名的相对优势越小，融合结果越平滑；k 越小，越信任单路的头部结果。
- 最终分数是各路贡献之和，按分数降序得到融合排名。

这个公式有两个重要性质。第一，它是尺度无关的，只要各路都给出排名，就可以融合，不需要做任何分数校准。第二，它天然惩罚"只在一路里排第一"的文档，因为两路都靠前的文档会得到两次贡献。实测在本文测试集上，融合后的召回率显著高于任一单路。

## 双路召回的工程要点

1. 两路都取相同的 top_k，但进入融合前建议各放大到 2 倍，给融合层留出足够候选，最后再截断。
2. 融合的并列分数必须有稳定的次级排序键，否则同分文档的顺序会随字典遍历顺序漂移，破坏可复现性。本系统使用"首次出现顺序"作为次级键。
3. 稀疏检索的中文分词必须处理无空格语言。字符二元组是经过验证的基线做法；本系统对中文使用字符二元组，对英文使用词元。

## 常见陷阱

陷阱一：用同一份语料评估召回率和精确率，却忘了评估必须在全新的检索管线上执行。运行期已经写入了数据的管线会污染评估结果，导致指标忽高忽低。

陷阱二：把 BM25 的 IDF 公式写成 ln((N - n + 0.5) / (n + 0.5))。当词项出现在半数以上文档时，这个值为负，会让高频词反过来压低得分。正确写法是 Robertson 形式 ln(1 + (N - n + 0.5) / (n + 0.5))，对任意 0 <= n <= N 都严格为正。

陷阱三：中文语料只有两篇文档时做 BM25 测试，目标词恰好出现在一篇里，IDF 退化为零，检索结果全空。单元测试语料至少要三篇，且目标词不能出现在半数文档中。
